# 担当（サブエージェント）への指示書の雛形

章の作成と仕上げ確認を担当に頼むときの指示書。§2・§3 の雛形の `{…}` を埋め、§4 の章ごとの差し込みを足して Agent ツールに渡す。担当は会話の文脈を持たないので、指示書だけで作業できるように書く。

## 1. 使い方

- 一時置き場は、そのセッションの scratchpad の下に `chNN`（作成）・`rvNN`（仕上げ確認）を作って使わせる。プロジェクトの中に写真を置かせない。
- 担当に変えさせるのは章のファイル 1 つだけ。docs・assets・tools・index.html・他の章は調整役が変える。
- 並列は 5〜6 人まで（[handoff.md](handoff.md)「進め方」）。
- 担当の報告を受けたら、調整役は「他の章で直したほうがよい所」を直すか plan.md「後で見直す所」に積み、進捗表を更新する。

```text
## 守ること
- 変更してよいのは `chapters/{NN}-{名前}.html` だけ。他の章に直すべき所を見つけたら、直さずに最後の報告に書く。
- tools/serve.sh は使わない（共有のポートを使うため）。tools/verify.mjs と tools/shot.mjs は自前のサーバーを立てる。
- 調査役（サブエージェント）は呼ばない（利用上限で一緒に止まり、結果が返らなくなるため）。
- 一度に全部を書かない。骨組み＋表紙＋場面1 を書いて検証 → 場面を1つずつ足して検証 → まとめ、の順で進める。
- 色は必ずクラスで付ける（直書きは禁止。ダークモードで壊れる）。右寄せは `t-end`（`t-r` は電波の色）。
- 事実は確かなものだけ。数値・規格・年は確信のあるものだけ書き、「約」「多くの場合」「2026 年時点」で較正する。模式図の誇張は本文か注記に「誇張」と書く。確信が持てない事項は書かないか、ぼかして書き、最後の報告に挙げる。WebSearch / WebFetch（ToolSearch で読み込む）で確かめてよい。手元で実測してよい（測った日と条件を書く。Cookie・識別子・家の実際のアドレスは書かない）。
- 文章は authoring.md §8 に従う。比喩で噛み砕かない。結論を先に。図を見れば分かることを本文で繰り返さない。位置で指さない。HTML に直接書く本文でバッククォートを使わない（`<code>` で書く）。
- 字数の予算（リード 70〜110 字、段階の本文 90〜160 字、補足 90〜140 字、図の説明 1〜2 文）を守る。

## 検証（完了の条件）
1. `node tools/verify.mjs --nav --overlap chapters/{NN}-{名前}.html` で、JS のエラー・はみ出し・横スクロール・リンク切れ・時刻送りの例外・未定義のクラスがすべて無い。文字の重なりの注意は、写真か tools/shot.mjs で確かめて直す（意図した重なりなら報告に理由を書く）。段階の行き来の注意は、乱数で変わる表示以外は onStep を直して消す（乱数は時刻を種にした疑似乱数にすると消える）。
2. `--shots <一時置き場>/shots --all-steps` で全場面・全段階の写真を撮り、Read ツールで**全部**見る（縦読み版は場面ごとに `*-phone-sK.png`）。動く札は止まる位置でも確かめる（`node tools/shot.mjs chapters/{NN}-{名前}.html --scene N --step K --at 0,1.5,3 --out <一時置き場>/at`）。authoring.md §9 の項目を1つずつ確かめて直す。
3. `--dark` を付けて撮り、表紙と場面2〜3枚を見る。

## 最後の報告（短く）
- 作ったファイルと、各場面の段階数
- 検証ツールの最終結果（`--nav` 付きの出力をそのまま）
- 自信のない事実・数値と、そう書いた理由
- 他の章で直したほうがよい所（ファイル名・行・理由）
```

```text

- 作業用の一時置き場（写真など）: {scratchpad}/rv{NN}（無ければ作る。プロジェクトの中に写真を置かない）

## 最初に読むもの
1. CLAUDE.md、docs/plan.md（「共通の例の値」「実測の記録」）、docs/authoring.md（仕様。全部。特に §9「よくある誤り」）

3. chapters/{NN}-{名前}.html（対象。通読）
4. 前後の章の関係する所: {章と場面}

## 確かめること
1. **見た目**: `node tools/verify.mjs --nav --overlap --shots <一時置き場>/shots --all-steps chapters/{NN}-{名前}.html` で全場面・全段階の写真を撮り、Read ツールで**全部**見る。動く札は止まる位置でも確かめる（`node tools/shot.mjs chapters/{NN}-{名前}.html --scene N --step K --at 0,1.5,3 --out <一時置き場>/at [--dark]` で、段階に入って何秒後かを指定して撮れる）。文字どうし・文字と図形の重なり、枠や図の外へのはみ出し、切れた札、前の段階の消し忘れ、矢印の向き、色の意味違い、10px 未満の文字。`--dark` でも数枚撮る。

- 直してよいのは chapters/{NN}-{名前}.html だけ。小さく的確に直す。場面の構成を作り直す必要があると判断したときだけ、理由を報告に書いたうえで最小限に。

- 調査役（サブエージェント）は呼ばない（利用上限で一緒に止まり、結果が返らなくなるため）。tools/serve.sh は使わない。
- 直したら `node tools/verify.mjs --nav --overlap chapters/{NN}-{名前}.html` を通し、直した場面の写真を撮り直して見る。
```
