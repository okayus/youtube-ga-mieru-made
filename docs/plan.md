# 全体計画 — YouTubeが見えるまで

「インターネットで YouTube の動画が見られるまで」を、電子の動きから画面の画素まで、途中を飛ばさずにアニメーションで追う教材。
全25章・6部。各章は1つの HTML（`chapters/NN-*.html`）で、表紙＋動く場面6つ＋まとめの8場面からなる。

## 読む順と、章どうしのつながり

```
第I部 電気          01 電子と電流 → 02 半導体とダイオード → 03 トランジスタ
第II部 計算機       04 論理ゲートと2進数 → 05 記憶 → 06 CPU → 07 入出力と周辺機器 → 08 画面と音
第III部 ソフトウェア 09 OS → 10 ブラウザ
第IV部 つながる     11 ネットワークの層 → 12 Wi-Fi → 13 Ethernetとスイッチ → 14 ホームルーター → 15 光回線 → 16 インターネットの骨格
第V部 約束ごと      17 DNS → 18 IP → 19 TCP・UDP・QUIC → 20 TLS → 21 HTTP
第VI部 YouTube      22 YouTubeのサーバー側 → 23 動画の圧縮 → 24 ストリーミングと再生 → 25 通しで見る
```

- 電子（1章）→ スイッチとしてのトランジスタ（3章）→ ビットと論理（4章）→ 記憶（5章）→ CPU（6章）と、下から積み上げる。
- 2章の LED・フォトダイオードは 15章（光回線）の光源・受光器に、6章のクロックと発熱は 3章の CMOS の充放電に戻ってつながる。
- 11章で家の中の機器配置と層モデルを先に見せ、12〜16章で物理的な道（電波・銅線・光）、17〜21章で約束ごと（プロトコル）を追う。
- 25章は「再生ボタンを押してから最初の画が出るまで」を1本の時間軸にして、各章へのリンクで振り返る。

## 共通の約束

- 作り方は `docs/authoring.md`。共通 CSS は `assets/base.css`、エンジンは `assets/engine.js`。
- 色の意味は全章で同じ: e 電子・電流・電気信号／h 正孔・＋電荷・高い電位／p 光／r 電波／d データ・パケット・ビット列／x 強調・変化・注意。映像の断片（動画のデータ）も d で描く（p は光だけ。光回線の上を映像が流れる図で区別がつかなくなるため）。
- 表紙の構成（目次）とまとめの用語表は必ず置く。まとめには「次の章へ」のリンクを置く。
- 検証は `node tools/verify.mjs --nav --overlap chapters/NN-*.html`（JS エラー、はみ出し、縦読み版の横スクロール、リンク切れ、時刻送り、段階の行き来、文字の重なり）。止まる位置や途中の姿は `tools/shot.mjs` で撮る。
- 他の章へのリンクは同じフォルダの相対パス（`href="14-router.html#s4"`）。`../` を付けない。
- 章は「作成（作った担当が全段階の写真まで確認）→ 別の担当による仕上げ確認 → 検証済み」の順に進める。第10〜14章では、作った担当の確認の後でも、仕上げ確認で各章十数か所の重なり・戻る操作の不具合・事実の誤りが見つかった。進捗表の「確認待ち」「確認中」はこの仕上げ確認のこと。

## 実測の記録（2026-10-12）

各章の担当が手元の回線（日本の家庭の固定回線 1 本）とログインしないヘッドレス Chrome 155 で測った値。章の本文には「例」「2026 年時点」を付けて使う。第25章の時間軸はこの値を土台にする。

- DNS: www.youtube.com は CNAME なしの A 8 個（142.251.150〜157.4）・AAAA 8 個、TTL 300 秒。地域によらず同じ答え（Anycast と推定）。動画の配信元は CNAME（TTL 1,800 秒）と HTTPS レコード（alpn="h3"）（第17章）
- 往復時間: www.youtube.com まで約 7〜12 ms（ping）。traceroute（mtr）で 6 ホップ（第17・18・20章）
- TLS: TLS 1.3、鍵交換 X25519MLKEM768、AES_128_GCM、ECH なし。証明書は *.google.com（SAN 65 個に *.youtube.com）、EC P-256、WE2 → GTS Root R4（ECDSA を使えない相手には RSA の WR2 → GTS Root R1 が届く）、有効期間 84 日、SCT は Google Argon2026h2 と Sectigo Elephant2026h2（第20章。連鎖と SCT は 2026-10-17 に Chrome 155 で取り直した値）
- HTTP: HTML は HTTP/2（Brotli 163 KB、展開 1.40 MB）、Alt-Svc の後は HTTP/3。base.js は展開 2.63 MB。googlevideo.com は最初から HTTP/3（第10・21章）
- 動画の断片: `/videoplayback?…sabr=1` への POST（本文は protobuf で再生位置と溜めた区間）。応答は application/vnd.yt-ump で、音声と映像の断片をまとめて返す。720p の再生で AV1（mp4）＋ Opus が選ばれた（第21章）
- 量と時間: 最初の 30 秒で要求 208 個・約 11 MB（映像と音声 6.9 MB）。最初の画は約 2.4 秒後。2 回目は 153 個がキャッシュから（第21章）
- 測り直し（2026-10-17、同じ URL・回線、Chrome 155.0.8059.39）: 要求 201 個・約 11.3 MB（映像と音声 7.0 MB、62%）、最初の画は約 2.3 秒。HTML は 163 KB → 1.42 MB（`<script>` の中が 97.4%）。断片の POST の本文は最初が 1.4 KB、以後は約 1.6 KB。プレーヤーの版は 5203c085 → 0229cd64 に変わっていた。最初の POST は 1.69 秒（generate_204 は 1.51 秒）（第21章）
- 音声とコンテナ（2026-10-17、各ファイルの先頭の数 KB を読んだ値）: AAC（itag 140）は 44.1 kHz、Opus（251）は 48 kHz・先頭は 20 ms ごと（確かめたのは先頭の約 70 個）・CodecDelay 6.5 ms・時刻の単位 1 ms・ファイル 3,433,755 バイト（初期化部分 0〜258、索引 259〜629。WebM の要素の大きさは ID・大きさ・中身を含む全体）。AV1 720p（398）は時刻の単位 12,800／秒、索引（sidx）は 38 項目（第23章）
- 再生の中（2026-10-17、ヘッドレス Chrome で 5 回再生、帯域は DevTools の通信の制限で絞った）: SABR の POST の本文の欄 23 はプレーヤーの帯域の見積もり（詳細統計情報の Connection Speed と一致）、18・19 はプレーヤーの大きさ 1337×752、28 は再生位置（映像が尽きている間は映像の端の 36,160 が入る）、17 は手動の画質のときだけ itag。残り 18 秒で 0.3 Mbps に絞ると約 31 秒で映像が尽き、音だけ 2.8 秒進んで全体が 1.5 秒止まり、144p で再開（制限を外すと断片 29 から 720p、溜めた 144p は取り直さない）。残り約 70 秒で絞ると 720p のまま止まらない。復号器は Dav1dVideoDecoder（ソフトウェア）。シークは溜めていない所へ 1.60 秒・溜めた所へ 0.02 秒。手動の画質変更は MediaSource を作り直して 0.5 秒（第24章）
- 計測の環境の注意（2026-10-17、25 章の作成者）: この回線では systemd-resolved 経由の AAAA の問い合わせが 0.2〜3 秒かかることがある（ルーターが AAAA に ANSWER 0・SOA なしで答える）。QUIC の 2 個目の Initial データグラムが 4 回とも失われ、PTO で 50〜190 ms 遅れた。21・24 章の時刻（generate_204 に 0.38 秒など）にも影響した可能性がある。DNS の時間と最初の画までの時間を「典型」として使うときは注意する
- QUIC の最初のデータグラム（2026-10-17、Chrome 155.0.8059.39 の netlog、QUIC を強制した初回接続）: UDP の中身は詰め物込みで 1,250 バイト（下限 1,200 より大きい）。ClientHello は X25519MLKEM768 の鍵共有を含めて約 1,877 バイトで、Initial パケット 2 個（データグラム 2 個）に分かれる。サーバーのデータグラムも 1,250 バイト（第18・19・20章）
