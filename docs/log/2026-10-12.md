## 2. 仕上げ確認で直した主な点（10〜18 章）

各章とも、作った担当とは別の担当が全段階の写真（明・暗・縦読み版）と本文を確かめ、その章のファイルだけを直した。重なり・はみ出し・札の止まる位置の修正は全章にあるので省き、内容と仕組みの修正を挙げる。

### 10 ブラウザ
- 戻ると前の見た目が残る所を 4 か所直した（場面2 のパーサ停止中の箱、場面3 の窓の幅、場面4 の動画層の色、場面6 の札と PTS）。
- HTML に直接書いた本文でバッククォートの記号がそのまま出ていた。
- 事実: 入力中の文字は検索候補のために送られている（Chromium の既定）。HTTP/2・3 に要求行は無いので「要求」と書く。クリックのヒットテストはメインスレッド。DNS と接続の確立は最初の 1 回だけ。「画質は JS が決める」は SABR に移りつつあるので削った。
- 実測: 視聴ページの HTML は圧縮前 1.4 MB、base.js は約 2.6 MB。youtube.com は HSTS プリロードに入っている。

### 11 ネットワークの層
- 例の値を共通の値にそろえた（PC 192.168.1.10、MAC）。
- 場面5 段階4 の `const` への再代入で、5.2 秒後に毎フレーム例外が出ていた。
- 色: IP を h、TCP とポートを r で塗っていたのを、ヘッダは無彩色・中身は d にした。
- 事実: 「ルーターはビット列を変えない」は誤り（MAC・TTL・NAT を書き換える）。「固定電話の網は回線交換」は「かつての」に（NTT は 2024 年 1 月に IP 網へ移行）。
- 調整役が後から直した所は §3。

### 12 Wi-Fi
- 場面4・6 の電波の弧が一度も描かれていなかった（始点と終点が同じ円弧）。
- 事実: 雑音を 20 MHz の値で計算していた（80 MHz の −89 dBm に）。日本の 2.4 GHz の重ならないチャネルは 3〜4 本、5 GHz は 20 本。WPA3-Personal の基本も CCMP。W56 の上限は 5.73 GHz。
- 端末の MAC を PC の共通の値に、BSSID を 13 章と同じ 02:11:22:33:44:F0 にした。
- 雑音の点と暗号文は時刻を種にした疑似乱数にした（`--nav` の注意が消える）。

### 13 Ethernet とスイッチ
- 事実: PAM-5 は 0 を含む 5 値をすべてデータに使う。プリアンブルと SFD は 0x55・0xD5。差動信号は差で ±1 V。10GBASE-T は 4 対で計 12.5 ビット。EtherType は 1,500 以下が長さ、1,536 以上がタイプ。MAC 表は約 300 秒見なければ消える。
- `s-rule-soft`（未定義）で区切り線が描かれていなかった。
- 例の値: YouTube の IP を 142.250.196.110、PC の MAC を共通の値、テレビを 192.168.1.5 にした。

### 14 ホームルーター
- 処理の順を「経路表 → NAT」に直した（送信元の書き換えは出口が決まった後）。
- 事実: DHCP は 2 往復（4 つのメッセージ）。conntrack は SYN/ACK の後 SYN_RECV。チェックサムを差分の更新と一致させた（0x7A12 → 0x7B12 → 0x00BF）。
- ロンゲストマッチの参照先を第16章に、外の第三者を 192.0.2.7 にした。

### 15 光回線
- 計算の誤り「2 段 × 3 段 ＝ 5 段」を「2 段 ＋ 3 段」に。場面4（局舎から 2 km）と場面6（5 km）の食い違いをそろえた。
- 事実: 上りの許可待ちは約 1 ms（NTT 2020 年の TTC セミナー資料）。通信量の伸びは年 3〜4 割（総務省 2018 年）。暗号は LLID ごとに別の鍵（NTT 技術ジャーナル 2005）。

### 16 インターネットの骨格
- 事実: Google は 2024 年から原則として IX のルートサーバーを使わない。中継器の間隔は約 60〜90 km。IX の route server を DNS の root server と区別して書いた。
- 確かめた値: 約 8 万 AS（CIDR Report 2026-10）、142.250.0.0/15 は AS15169、海底ケーブル約 570 本（TeleGeography 2025）、Topaz は 16 対・240 Tbps、故障の 7〜8 割は漁具と錨（ICPC）。

### 17 DNS
- 作成者の実測はすべて正しかった（plan.md「実測の記録」）。
- 事実: youtube.com の 2005 年の登録者を Google としていた（Google の買収は 2006 年）。RA は Recursion Available。Android のプライベート DNS は主に DoT（一部の事業者は DoH）。
- 表紙の注記の矛盾を直し、AAAA の例を共通の値にした。

### 18 IP
- 17 か所。参照先の場面、ホップ数（例 9 台、実測 6 ホップ）、PPPoE を「媒体」と呼んでいた所、フレッツの MTU 1,454 推奨の注記、traceroute の一巡（約 28.7 秒）が段階の時間より長く後半の行が出なかった所、ICMP に入る写しは「少なくとも先頭 8 バイト」。
- 確かめた値: チェックサムと各欄、IPv6 の普及率（APNIC 2026-10-09 で日本 61.6%・世界 43.6%）、ping の初期値 128、UDP の traceroute の最後は Port Unreachable。

## 4. 19〜24 章で確かめきれていない事実

作成者が申告したもの。仕上げ確認で確かめて、直すか言い切りを弱める。実測した値は plan.md「実測の記録」にある。

- **19 章**
  - Chrome で YouTube は「多くの場合 QUIC」（割合の一次資料なし）。
  - Chrome が QUIC と TCP を並べて試し、失敗を覚えること。
  - CUBIC が各 OS の既定であること。
  - Google が YouTube の配信に BBR を使うこと（2017 年の発表と 2024 年の IETF 119）。
  - QUIC が NAT の行を保つ PING。
  - 「QUIC は 2013 年に公開」「QUICHE は Chrome と Google のサーバーで共通」（記憶による）。
- **20 章**
  - Chrome のルートの数「約 100」（Chromium のソースで数えた）。
  - ECH は Chrome 117（2023 年）から。
  - 暗号化した通信の量の形から動画を見分けた 2017 年の研究。
  - AES-NI は 2010 年から。
  - X25519 を破るのに約 2^126 回。
  - SCT を示せない公開の証明書の扱い。
- **21 章**
  - SABR の「サーバーが次の断片を選ぶ」細部（第三者の資料）。
  - Chrome が UDP の通らない網で HTTP/2 に戻る動き。
  - HPACK の数値は nghttp2 で数えた例。
  - Cookie の Domain による付き方。
- **22 章**: 作成者の報告なし。PUE 1.09（2026 年第2四半期までの 12 か月、印西 1.10）は確認済みと途中で述べていた。Argos の論文を探す途中だった。
- **23・24 章**: 作成者の報告なし。24 章の作成者は帯域を絞った再生を実測していた（結果は一時置き場にあり、失われる）。
