## 書き方

- ファイル名は `YYYY-MM-DD-題.md`（題は英小文字・数字・ハイフン）。日付はニュースが出た日。
- 書いたら `node tools/build-news.mjs` で、ページ（`news/<同じ名前>.html`）、一覧のページ（`news/index.html`）、月のページ（`news/YYYY-MM.html`）、ノートのデータ（`news/news-data.js`）、上の 2 つの表を作り直す。続けて `node tools/verify.mjs news/index.html news/YYYY-MM.html news/<同じ名前>.html` で確かめる。`.html` と `news-data.js` は手で直さない。
- 見出しがページの場面になる。
  - `#` は題。題の後の箇条書き（出典・調べた時点など）は表紙に出る。
  - `## 要点` は表紙のリード。最初の文に、どの層の話かを書く。一覧のページにはこの 1 文が出る。
  - ほかの `##` が場面 1 つになる。上部バーのタブの名前は `## 見出し <!-- tab: 短い名前 -->` で付ける。
  - 場面の中の `###` は、1画面版で横に並ぶ列 1 つになる。短い節は `###` にして 1 つの場面にまとめ、1 画面に収まらない節は `##` で場面を分ける。
- ノートの型は 3 つある。脆弱性と事故は「事故の型」、機能の追加・リリース・技術記事は「更新の型」で書く。どちらも、当てはまらない節は省く。毎朝の自動のノートは、下の「日刊の型」で書く。
- 事故の型の節の順:
  1. 要点
  2. 確かなことと、確かでないこと: 項目・内容・出どころ・確かさの表。公式・研究者の報告・未確認を書き分ける。
  3. どの層の話か: 層・このニュースで起きること・章と場面の表。教材に無い層は「教材に無い」と書き、近い場面を添える。
  4. 層ごとの守り（または影響）: 対策や影響が層ごとに違うときだけ置く。
  5. 追って確かめること。
  6. 出典。
- 更新の型の節の順（場面は 6 つまで。手本は [MoonBit の形式検証](2026-09-14-moonbit-formal-verification.md)）:
  1. 要点
  2. 何が変わるか（タブは「層」）: 層・このニュースで起きること・章と場面の表。表の前に、変更の種類（インターフェースの追加・破壊的変更・実装だけの変更）と、働くのがビルド時か実行時かを書く。
  3. 何を解決するか（タブは「解決」）: 困っていたことと以前の回避策、新しいやり方、解決しないこと。
  4. 仕組み: 教材に無い前提のうち、ニュースの中心にあるもの 1 つを説明する。無ければ省く。
  5. 前提知識（タブは「前提」）: 概念・このニュースでの役割・章と場面の表。下の層から、依存の順に並べる。教材に無い概念は、章と場面の欄を「教材に無い」で始め、近い場面を添える。
  6. いつ使えるか（タブは「段階」）: 提案・仕様・実装・出荷・普及のどこにあるかを日付つきで書き、誰が何をすれば効くかを書く。
  7. 予想との差・追って確かめること・出典: 調べる前に書いた予想（層・前提・解決する問題）と、ノートとの差を残す。
- 更新ではない記事（比較・感想・解説）も更新の型で書く。2 は「どの層の話か」にして、違いが働くのがビルド時か実行時かで分ける。予想に問いが含まれるときは、答える場面を 1 つ足し、「いつ使えるか」は「記事の後に変わったこと」として 7 に入れる。手本は [関数型プログラマからみた Rust](2017-04-04-rust-from-functional-programmers.md)。
- 章へのリンクは公開版の場面を指す（`https://sukitooru.shiraoka.workers.dev/chapters/09-os.html#s3` は第9章 場面3）。ページを作るときに相対パスに直り、表紙と一覧の全 43 章の帯に印が付く。章のその場面の見出しには「この場面のニュース N ›」の札が出る。
- 「層」のタブの場面の表（列は「層 | 起きること | 章と場面」の 3 つ）は、ページでは層の歩きになる。1画面版では表の行が段階になり、説明欄に行の文と章と場面、右の層の図に、いまの行の層（x の枠）と、前の行の層から伸びる線が出る。縦読み版では表を縦に並べ、図には全部の行の道筋を出す。
  - 行の 1 列目は、段階の題と行の一覧に出る。短く書く。太字の行は一覧でも太字になる。
  - 章と場面の欄のリンクと、図の ↓ の札は、章の場面を板に開く（章へ移らない）。リンクの直後に「の段階4」と書くと、板はその段階から開く。
  - 欄を「教材に無い」で始めた行は、近い場面の層を破線の枠で示す。その行が `missing` の概念の名前を含めば、図の下の破線の札も光る。
  - 表が 2 つある、列が 3 つでない、場面を `###` で列に分けた、行が 1 つだけ、のどれかなら表のまま出す。
- ノートの層は、章へのリンクの先の場面の層（`assets/layers.js` の登録簿）の和で、自動で決まる。表紙と一覧のカードに層の札が出て、一覧の「層の地図」に数えられる。
  - 中心の層（札の先頭。太字）は、`## 要点` の最初の文に出る「第N章」「第N章 場面K」の層で最も多いもの（同数は「層」のタブの場面の表で多い方）。その文に章が出なければ、「層」のタブの場面の表で最も多い層。
  - 決まった中心が違うときは、題の次の行（日刊は印の次）に `<!-- layer: runtime -->` と書く。先頭が中心の層になり、書いた層はノートの層に加わる。id は `assets/layers.js` の `layers`（`node tools/layercheck.mjs --list` で一覧が出る）。
- 教材に無い概念は、題の次の行（日刊は印の次）に `<!-- missing: WebAssembly、契約 -->` と書く。「、」で区切り、8 個・各 40 字まで。一覧の場面「教材に無い」に、出たノートの数と近い場面が並ぶ。
  - 名前は、表や本文に「教材に無い」と書いた行の語にする。その語（「（」より前）と「教材に無い」を含む行・項目・段落の、章の場面へのリンクが「近い場面」になる。説明を足すなら `ZIP（zlib.ZipFile）` のように丸括弧で後ろに付ける。
  - 前のノートに出た概念は同じ名前で書く（一覧の「教材に無い」か、`grep -h '^<!-- missing:' news/*.md` で確かめる）。3 件のノートに出た概念には、章の候補の印が付く。
- タグは、題の次の行（layer の印があればその次、missing の印の前）に書く。語彙の正本は [assets/tags.js](../assets/tags.js) で、`node tools/tagcheck.mjs --list` が層ごとの一覧を出す。表紙の題の下と一覧のカードに角の丸い札が出て、押すとタグのページ（`news/tag-<id>.html`）を開く。タグの一覧は `news/tags.html`。
  - `<!-- tags: Linux、kernel、解放後の使用 -->` は内容のタグ。ノートが何の話かを、語彙の正規の名前（name）で、中心の語から「、」で区切って書く（別名は書かない）。目安は、中心の製品・言語・プロトコル、問題や仕組みの種類、脆弱性と事故なら「セキュリティ」。名前が出てくるだけの物は付けない。
  - `<!-- prereqs: メモリ安全、デシリアライズ -->` は前提のタグ（任意）。読むのに要る知識のうち、ノートの層（四角い札）より細かいもの。層の名前にあたる広い語（OS、TLS、HTTP など）と、内容のタグと同じ語は書かない。表紙では「前提」の後に破線の札で出る。
  - `<!-- tag-candidates: Gleam -->` は語彙に無い語（任意）。内容のタグにしたい語だけを書く。タグの一覧の「候補」に、出たノートの数と並ぶ。持ち主が語彙に足すと（name か alias）、そのノートの内容のタグになる。語彙に入れない語は assets/tags.js の `ignore` に入れると、候補から消える。
  - 語彙を足すときは、mazuoboeru に同じ概念のタグがあれば、使われた数の多い形を正規の名前にし、ほかの形を別名にする（kokemusu の石がそろう）。正規の名前を変えるときは、前の名前を別名に残す（ページを作るときは別名を正規の名前に読み替えるので、既にあるノートを直さなくてよい）。直したら `node tools/tagcheck.mjs` で確かめる。
- 文章は [docs/authoring.md](../docs/authoring.md) §8 に従う。
- 起きたことを図で動かすときは、場面に台本を書く（下の「動きの場面（台本）」）。

## 動きの場面（台本）

`##` の場面の中に台本（```` ```anim 部品 ```` のブロック）を書くと、その場面が動きの場面になる。1画面版では左に台本より前の文（リード）・段階の説明欄・台本より後の文（補足）、右に部品が描く図が出る。縦読み版は章の動く場面と同じ並び。ノートには JS を書かない。台本は登場する物と、段階ごとに出す・変える物だけを書き、手で書いた部品（`assets/parts/`）が描く。見本の台本は [部品の見本の「台本の部品」](https://sukitooru.shiraoka.workers.dev/parts.html?set=anim) で動かせる。手本は [Linux の TCP のノート](2026-10-15-linux-ipv4-tcp-uaf.md) の場面「仕組み」（mem）と、[eMudhra のノート](2026-10-20-emudhra-ca-key-compromise.md) の場面「連鎖」（tree）・「経緯」（timeline）。

````

- 見出しの行: `title:`（図の題。必須）、`caption:`（図の説明。120 字まで。ページでは「図N」の後に出る。必須）、`note:`（図の右上の小さい注記。任意。縦読み版では横に送った先に出るので、読まなくても分かることだけ）。title と note は図の上の 1 行に並ぶので、「title の幅 × 1.3 ＋ note の幅」は 78 まで。mem だけ列の見出し `left:`・`right:` も書ける。
- 登場する物は「種類 id: 中身」の 1 行。id は英小文字で始め、英小文字・数字・`_` で 16 字まで。`| 小さい札` は省ける。札の幅には部品ごとに上限があり（漢字・かな・全角の記号を 1、英数字を 0.56 と数える）、超えると作るときに止まる。`` `…` `` で囲んだ所は等幅で描く。札が箱に入らなければ、部品が 2 行に折り、それでも入らなければ字を小さくする（上限いっぱいの英字の札は小さくなりやすい）。
- 段階は `step: 題`（30 字まで）で始め、続く行が本文（160 字まで。目安は 60〜160 字で、図の札で足りる段階は短くてよい。`` `コード` ``・`**太字**`・`[リンク](URL)` が使える。章の場面へのリンクは板を開き、リンクの直後に「の段階4」と書くと板はその段階から開く。日刊は段階を書かない）。段階は 2〜6 つ。本文の行は「英小文字の語: …」の形にしない（操作の行として読み、下の 9 つのどれでもなければ誤りにする）。字数は記号（`` ` ``・`**`・リンクの URL）を外して数える。本文と caption に章の記法の `[[…]]` と `{e|…}` は使えない（強調は `**太字**`）。
- 図の位置は全部の段階で変わらない。隠した物も場所を取る（seq の行、timeline の出来事も）。同じ所の前と後（修正の前と後など）を 1 枚で見せるときは、隠す物と出す物を分けて宣言し、`set:` で札を替える。
- 操作の行（その段階の中に書く）:
  - `show: id …` その段階から出す。どこかの段階の `show:` に出る物は、その段階まで隠れている。どの `show:` にも出ない物は、最初から出ている。`hide: id …` はその段階から隠す。
  - `x: id …` その段階だけ x（注目）にする。書かなければ、その段階で出た物・変わった物が x になる（何も出ず変わらない段階は注目なし）。`x: -` は注目なし。
  - `bad: id …` その段階から壊れた物（破線）にする（解放した区画、漏れた鍵、偽の証明書など）。`ok: id …` で戻す。
  - `set: id = 札 | 小さい札` その段階から札を替える。`|` が無ければ小さい札はそのまま、`| -` で消す。
  - `point: p -> b`（mem だけ）ポインタ p の指す先を b にする。`-` で何も指さない。
  - `send: a -> b: 札`（mem・stack・boxes・tree）その段階だけ、a から b へ粒が流れ、札が出る。boxes は line で、tree は親子か edge で結んだ 2 つのあいだだけで、その線はその段階で見えていること。1 段階に 2 つまで（stack は 1 つ）、同じ 2 つのあいだは 1 つ（行きと帰りは段階を分ける）。send は注目を変えない（send だけの段階で両端を注目にするなら `x:` に書く）。
  - `down: id -> 19-tcp.html#s2.1: つなぎの一文` その段階だけ、id に掘り下げの印を付ける（押すと章の場面を板に開く。1 段階に 3 つまで。行き先は公開版の URL でもよい）。行き先の章の場面も、ノートの層と章の帯に数える。つなぎの一文（60 字まで）は板の上端に文字のまま出る（`` ` `` などの記号を使わない）。上の段階の語（題・本文・図の札の語）で始め、行き先の場面が説明する仕組みの語で終える（[docs/authoring.md](../docs/authoring.md) §5.5）。行き先の章の説明を短く言うのはよいが、ニュースの事実は足さない。行き先の章の例がニュースの物と別の実装なら（ブラウザのイベントループと Node など）、同じだと言い切らない。同じ物から同じ場面へ 2 つ張らない（一覧に段階が出ないので見分けられない）。日刊のノートは段階の番号を書かない（`19-tcp.html#s2`。板は場面の初めから開く）。
- 線の通り道: boxes の line は箱の真ん中どうしを結ぶ直線なので、途中の升目にある箱の上を通る結び方（`1,1` と `3,1` の間に `2,1` の箱がある、など）は誤り。tree の edge も、両端のほかの箱の上を通ると、ページを開いたときに部品が誤りを出す（木や子の宣言の順を入れ替えて、2 つを近くに置く）。
- 置き場所: 台本は `##` の場面に 1 つ。その場面は `###` の列に分けない。台本の ``` の前と後には空行を置く（箇条書きの直後に置くと、箇条書きの続きに読まれるので誤りにする）。「要点」と「層」の場面には置けない。台本より前の文はリード（110 字まで）、後の文は補足（1 段落 140 字まで、2 段落まで）として、1画面に収まるように書く。どちらも段落だけにする（箇条書き・表・引用・コードは別の場面へ）。検査が字数と形を確かめる。
- 既にある場面を台本にするときは、もとの文の事実を段階の本文・リード・補足・図の札に配り直し（札に出した事実は本文に書かなくてよい）、入らない事実は別の場面に移す（消さない）。もとの文の章へのリンクは、段階の本文のリンクか `down:` に移す。
- 図の中の事実は本文と同じ扱いにする。ノートに書いていない物は描かない。ノートが名前を書いていない物（盗んだ物の送り先など）や、例として置いた名前・値（要求 1・要求 2 など）は、ノートの言葉の範囲で描き、`caption:` に「模式」「例」と書く。
- 繰り返さない: リードは場面の結論（何が起きたかの要約）を 1〜2 文で言い、段階の本文はその細部を図に沿って言う。同じ文を 2 度書かない。図の札に出ていることを本文で描き直さない（本文は図で分からない理由・数値・名前を書く）。ほかの場面と事実が重なるのはよいが、文を写さない（「層」の表の文を段階の本文に写さず、図で見せる言い方にする）。
- 重なり: send の札と掘り下げの印の札が、ほかの札に重なることがある。`verify.mjs --overlap` が知らせるので、箱の配置（boxes の `@ 列,行`）や札の長さを変えて逃がす。
- 確かめ方: `node tools/build-news.mjs` が台本を検査し（日刊の検査 `tools/news-pr-check.mjs` と同じ `assets/anim-script.js`）、誤りは行番号つきで止まる。ノートに書く前の試しは `parts.html?part=mem&src=<URL エンコードした台本>`。続けて `node tools/verify.mjs --nav --overlap --drill news/<ノート>.html`。
- 部品で描けない仕組みは、詳しいノートに限り、手書きの部品 `news/anim/<名前>.js`（`YT.parts.define` で登録する。作り方は [docs/authoring.md](../docs/authoring.md) §5.6）を ```` ```anim 名前 ```` で使える。手書きの部品の台本は、種類と操作の名前を部品が決める（形は同じ「種類 id: 中身」と「操作: 値」）。日刊のノートは使えない。

## 日刊の型

毎朝、話題の tech ニュースを 1 件選んで自動で書く短いノート。選び方と手順は [docs/daily-news.md](../docs/daily-news.md)。人が予想を書いてから調べる詳しいノート（事故の型・更新の型）とは別に置く。手本は [1960 年代の論理 IC「Signetics ST680A」の解析](2026-11-08-dtl-nand-chip-reverse-engineering.md)。

- 1 行目は `# 題（YYYY-MM-DD）`。日付はファイル名と同じ、ニュースが出た日。
- 題の次の行に、行だけの印 `<!-- kind: daily -->` を置く。一覧に「日刊」と出て、プルリクエストの検査（`tools/news-pr-check.mjs`）の対象になる。
- 印の次の行に `<!-- layer: 中心の層の id -->` を置く（要点の最初の文で書いた層。id は上の「書き方」）。その次の行に内容のタグ `<!-- tags: … -->`（1〜5 個）を置き、あれば続けて `<!-- prereqs: … -->`（4 個まで）、`<!-- tag-candidates: … -->`（3 個まで）、教材に無い概念の `<!-- missing: … -->` を置く（書き方は上の「書き方」）。検査が、layer の id が登録簿にあること、タグが語彙の正規の名前だけで数が収まること、候補が語彙に無いこと、missing の書き方を確かめる。
- 題の後の箇条書き（表紙に出る）は 3 つ。短く書く。長いと表紙が 1 画面に収まらない。
  - 出典: 一次情報（リリースノート・仕様・勧告・公式の記事・作った本人の記事）へのリンクと、発行元・日付。1〜2 文。
  - 話題: どこで話題になったか（Hacker News の点数、はてなブックマークの数など）と、その時点。1 文。
  - 調べた時点: 日付と、決まり文句「日刊のノート（自動で選んで書いた）。人は確かめていない。」。続けて、実行して確かめたことを 1 文で書く（無ければ「実行して確かめたことは無い。」）。道具と版は「出典と確かさ」に書く。
- `## 要点` は 3〜4 文。最初の文に、どの層の話かを書く。
- 場面（要点のほかの `##`）は次の 3 つ。
  1. `## どの層の話か <!-- tab: 層 -->`: 表の前に、種類（事故・機能の追加・破壊的変更・実装だけの変更・解説・作ったものや調べたものの報告）と、働くのがビルド時か実行時かを 1〜2 文で書く。ソフトウェアでない話題は、作るときと動くときのどちらの話かを書く。表は層・このニュースで起きること・章と場面で、2〜6 行。ページでは行が層の歩きの段階になる（上の「書き方」）。検査は、この 3 列と行の数を確かめる。
  2. `## 中身 <!-- tab: 中身 -->`: `###` の列を 2〜3 つ。更新は「困っていたこと」「新しいやり方」「解決しないこと」、事故は「起きたこと」「原因」「対策」、解説は「分かったこと」「仕組み」「教材との違い」。見出しの言葉は、中身に合わせて変えてよい。
  3. `## 前提と出典 <!-- tab: 前提 -->`: `### 前提知識` は概念・このニュースでの役割・章と場面の表（5 行まで。下の層から）。`### 出典と確かさ` は出典の箇条書き（一次情報を先に）と、確かめたことの道具と版、確かめていないこと、出典どうしの食い違い。
- 動きの場面（任意）: 起きたことが部品（上の「動きの場面（台本）」の 6 つ）で描けるときだけ、「層」と「中身」の間に `## 何が起きたか <!-- tab: 動き -->` を置き、1〜2 文のリードと台本を書く（補足は置かない）。台本は 1 つ、部品は 6 つのどれか（手書きの部品は使えない）。描けないときと迷うときは置かない。台本には起きたことの順と形（何がどこへ渡り、どこが壊れたか）を描き、その事実は「中身」の列に書かない。「中身」には台本に入れない事実（時刻と数、影響の大きさ、台本に描かない原因、対策）を書く。
- 大きさは 12,000 バイトまで（動きの場面を置いたら 15,000 バイトまで）。検査は、場面が 2〜4 つで 16,000 バイトまでなら通す（余裕を持たせてある）。
- 章と場面へのリンクは、章のファイルを開いて中身を確かめた場面だけに張る。2 つ以上の場面に張る（検査が確かめる）。段階の番号は書かない。教材に無い層・概念は「教材に無い」と書き、近い場面を添える。
- リンクは `https://` か `http://` で始まる URL だけ。https で開ける所は https で書く。URL に `)` を含むリンクは、参照の形（`[文字][名前]` と、行頭の `[名前]: URL`）で書く。
- 予想との差の場面は置かない。
