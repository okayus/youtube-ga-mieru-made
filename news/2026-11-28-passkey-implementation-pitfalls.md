## 要点

公開鍵の署名（第20章 場面4）で利用者を確かめるパスキーについて、仕組みと、実装の落とし穴を説明する記事である。端末の認証器が鍵の対を作ってサーバーには公開鍵だけを預け、サインインのたびにサーバーの出す乱数（チャレンジ）に秘密鍵で署名する。ブラウザや OS がページの名前とパスキーの名前（RP ID）を比べるので、偽のサイトでは本物向けの署名を作れない。記事は、安全さはサーバーの実装にも大きく掛かると書き、Swift で作った見本で確かめの手順を示す。

## 中身 <!-- tab: 中身 -->

### サーバーの落とし穴

- 記事は ITmedia の記事を引き、ドイツの大学がパスキーに対応した 103 のサイトを調べて、すべてに実装の弱点を見つけ、66% は本人を確かめ直さずにパスキーを足せたと書く。
- パスキーを足すときと登録し直すときは、直前に本人を確かめ直す。乗っ取ったセッションで攻撃者が自分のパスキーを足すと、ずっと入れるからである。
- 受け入れる署名の方式を絞る。見本は ES256 と RS256 だけを許す（仕様の番号は -7 と -257）。EdDSA（-8）は、使ったライブラリ webauthn-swift 1.0.0-beta.4 が扱わないので外した。
- パスキー 1 つを多要素の認証とみなすなら、`userVerification: "required"` で頼み、認証器のデータの UV のフラグ（生体認証などで本人を確かめた印）をサーバーで確かめる。`"preferred"` では UV が 0 で返ることがある。

### 同期と運用

- 署名のカウンタ（signCount）は、写した認証器を見つけるための数である。記事は、同期するパスキーでは 0 のままが普通だと書く。仕様は、カウンタを持たない認証器は 0 のままにすると決め、どちらかが 0 でなく新しい値が前の値以下のときだけ、写しの疑いとする。見本は、そのとき断らずに記録する。
- 仕様は、同期できる鍵かを示す BE のフラグが、登録の後に変わらないと決める。見本は、保存した値と違えば断る。ライブラリのこの版は確かめないので、アプリの側で足した。
- サーバーで消したパスキーは、端末に残って候補に出続ける。記事は、Signal API で端末の側へ知らせることを勧める。
- 端末をなくした人を救う回復の手順を先に決め、回復がいちばん弱い所にならないよう、本人の確かめと知らせを強くする。

### 教材との違い

- 教材の TLS（[20章 場面4][20-4]）では、署名で本物かを確かめられる側はサーバーで、その公開鍵は認証局が署名した証明書に入って届く。パスキーで確かめられる側は利用者の鍵を持つ認証器で、公開鍵は登録のときにサーバーへ直接渡る。見本は、認証器の出どころの証明（attestation）を求めない。
- 教材の鍵交換（[20章 場面3][20-3]）は、接続のたびに作って捨てる一時の鍵を使う。パスキーの鍵の対は、消すまで同じものを使う。

### 出典と確かさ

- [記事](https://zenn.dev/kantacky/articles/b5a03eab70c7b1)（Kanta Oikawa、Zenn、2026-11-28 08:00 JST。ページのデータの公開と更新の時刻も同じ）。仕組みの説明・落とし穴・見本の作りとコードは、ここから取った。
- W3C の [WebAuthn Level 3](https://www.w3.org/TR/webauthn-3/)（2026-08-25 の勧告）。RP ID の範囲と関連する名前の扱い、クライアントのデータの欄、認証器のデータの形（37 バイト以上）とフラグ、署名する範囲、カウンタの比べ方、BE のフラグ、チャレンジの長さ（16 バイト以上を勧める）を、ここで確かめた。記事が張るのは Level 2（2021-04-08 の勧告）で、RP ID の範囲・署名する範囲・カウンタの比べ方は同じ。
- 手元で確かめたこと: Node.js v22.23.5 の crypto で P-256 の鍵の対を作り、認証器のデータ（37 バイト）とクライアントのデータの SHA-256 をつないだものに ES256 で署名した。同じデータでは確かめに通り、クライアントのデータのオリジンを別の名前に替えると通らなかった。2026-11-28 20:19 UTC に curl 8.5.0 で見本の RP ID（`passkey.kantacky.com`）の AASA を取ると、HTTP/2 の 200・`application/json`・転送なし・`max-age=300` が、Apple の CDN からは 200・`application/json`・`max-age=3600` が返った。
- 確かめていないこと: 103 のサイトの調査（元の論文は読んでいない）、同期するパスキーの signCount が 0 であること（記事による）、iOS の API が使える版、webauthn-swift の振る舞い、見本のリポジトリの中身。はてなブックマークのコメントは読んでいない。
