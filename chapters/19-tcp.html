TCP・UDP・QUIC

IP はパケットを相手の機器まで運ぶが、順番も到着も約束しない（第18章）。その上で、機器の中のどのプログラム宛てかをポート番号で分けるのがトランスポート層の TCP・UDP・QUIC で、TCP と QUIC は抜けた分を送り直し、送る速さを網の混み具合にも合わせる。この章では、ポート、TCP の接続の始め方・番号と再送・速さの決め方、何も足さない UDP、UDP の上で TCP と TLS の仕事をまとめた QUIC を順に見る。Chrome で YouTube を見るとき、動画の断片は多くの場合 QUIC で届く。

1ポート — 機器の中の受け取り手を 16 ビットで指す

16 ビット443 ／ 535 つ組

IP アドレスが指すのは機器まで。機器の中のどのソケットに渡すかは、TCP・UDP のヘッダの先頭にある 16 ビットのポート番号で決まる。1 本の通信は、プロトコルと両端の IP・ポートの 5 つの値で見分ける。

Linux は ss -tunap、Windows は netstat -ano で、5 つ組とソケットの持ち主が一覧できる。NAT（第14章）を通ると、サーバーから見た組は 203.0.113.5:40001 → 142.250.196.110:443 に替わる。

23-way ハンドシェイク — 番号の始まりを伝え合ってから送る

SYN → SYN/ACK → ACKISN 32 ビットTIME_WAIT

TCP はデータの前に、SYN・SYN/ACK・ACK の 3 個のパケットで、両端の番号の始まり（初期シーケンス番号）と、1 個で受け取れる大きさを伝え合う。そのため最初のデータは、少なくとも 1 往復待たされる。

家のルーターの状態表（第14章）は、通るパケットを見て 1 行を SYN_SENT → SYN_RECV → ESTABLISHED と進める。両端の状態の名前を借りて、接続を途中から見た段階を表している。両端の状態は ss -tan で見える。

3シーケンス番号と ACK・再送 — 抜けた所だけ送り直す

累積 ACK重複 ACK 3 個SACK

TCP はデータの 1 バイトごとに番号を振り、受け手は次に欲しい番号を ACK で返す。送り手は ACK が来ない所だけを送り直す。途中で順番が入れ替わっても失われても、アプリには元の順のバイト列が渡る。

受け手はチェックサムが合わないセグメントも黙って捨てる。壊れたときも失われたときと同じく、ACK が来ないことから送り手が送り直す。Ethernet の FCS で捨てたフレーム（第13章）も、こうして TCP が埋める。

4ウィンドウと輻輳制御 — ACK を待たずに送れる量を決める

速さ ≒ ウィンドウ ÷ 往復時間初期 10 個CUBIC ／ BBR

送り手は ACK を待たずに、ウィンドウの分だけ先に送る。速さはおよそウィンドウ ÷ 往復時間。ウィンドウは、受け手の空きと、網の混み具合から送り手が見積もる量の小さいほうで決まる。

QUIC も同じ考え方の輻輳制御を、カーネルではなくブラウザとサーバーのプログラムの中に持つ（初期ウィンドウは同じく 10 個分、RFC 9002）。再生する画質は、こうして決まる速さの変化を見て選ぶ（第24章）。

5UDP — 番号と長さだけを付けて送る

ヘッダ 8 バイトRFC 768（1980）DNS・通話・ゲーム・QUIC

UDP は、ポート番号と長さとチェックサムの 8 バイトだけを付けて、データを 1 個ずつ IP に渡す。接続の手順も、順番の保証も、再送も無い。足りない仕事は、使う側のプログラムが自分の都合で作る。

行を消すまでの時間は機器で違う。RFC 4787 は 2 分以上を求めるが、30 秒で消える例もあると RFC 9308 は書く。UDP を通さない網も数 %（2016 年の調査で 3〜5%）あり、そこでは QUIC が使えない（6「QUIC」）。

6QUIC — UDP の上で、TCP と TLS の仕事をまとめる

UDP 443TLS 1.3 を組み込むRFC 9000（2021）

QUIC は UDP 443 番の上で、TCP の仕事と TLS 1.3 の暗号化をまとめて行う。HTTP/3 はこの上で動く。Chrome で YouTube を見るとき、動画の断片は多くの場合 QUIC で届く。

Google が 2013 年に公開した独自の QUIC を IETF が作り直し、RFC 9000〜9002（2021 年）になった。実装は Chrome と Google のサーバーで共通の QUICHE。鍵の決め方と証明書は第20章で見る。

7まとめ — 届け先を分け、抜けを埋め、速さを合わせる

  1. ポート番号は 16 ビットで機器の中のソケットを指し、サーバーは決まった番号、送り手は一時ポートを使う。1 本の通信は 5 つ組で決まる（1）。
  2. TCP は SYN・SYN/ACK・ACK で初期シーケンス番号を伝え合ってから送るので、データは 1 往復後、TLS を足すと要求は 2 往復後になる（2）。
  3. 番号はバイトごとに振り、ACK は次に欲しい番号を返す。重複 ACK 3 個かタイムアウトで、抜けた所だけを送り直す（3）。
  4. 速さ ≒ ウィンドウ ÷ 往復時間。輻輳ウィンドウは倍々に増やして損失で減らし、送るのは受信ウィンドウとの小さいほう（4）。
  5. UDP はポート・長さ・チェックサムの 8 バイトだけで、接続も順番も再送も無い。ルーターは UDP の行を時間で消す（5）。
  6. QUIC は UDP 443 の上で TLS 1.3 と一体になって 1 往復で始まり、独立したストリームと接続 ID を持つ。UDP が通らなければ TCP に戻る（6）。
ポート番号16 ビット（0〜65,535）。0〜1023 はよく知られたポート（443 HTTPS、53 DNS）。送り手の一時ポートは OS が選ぶ（Linux 32768〜60999、Windows・macOS 49152〜65535）。第13章のスイッチのポート（差し込み口）とは別。
5 つ組プロトコル・送信元 IP・送信元ポート・宛先 IP・宛先ポート。カーネルはこれでパケットをソケットへ振り分ける。
シーケンス番号・ISNデータの 1 バイトごとの 32 ビットの番号。初めの値（ISN）は接続ごとに予測しにくく選ぶ。SYN と FIN も番号を 1 つ使う。
TCP の状態LISTEN・SYN_SENT・SYN_RECV・ESTABLISHED・FIN_WAIT_1/2・CLOSE_WAIT・LAST_ACK・TIME_WAIT など。TIME_WAIT は Linux で 60 秒。
ACK・SACKACK は次に受け取りたいバイトの番号で、それより前を全部確かめる（累積 ACK）。SACK は届いた範囲を最大 4 つ（時刻のオプションと併せると 3 つ）添える（RFC 2018）。
再送重複 ACK 3 個で行う高速再送と、RTO が切れて行う再送。RTO の最小は RFC 6298 で 1 秒、Linux は 200 ms。
ウィンドウACK を待たずに送ってよい量。受信ウィンドウ（受け手の空き）と輻輳ウィンドウ（送り手の見積もり）の小さいほう。
輻輳制御網の混み具合に合わせて輻輳ウィンドウを変える仕組み。初期 10 個（RFC 6928）、スロースタート、輻輳回避、CUBIC（RFC 9438）、BBR。
UDPヘッダ 8 バイト（ポート 2 つ・長さ・チェックサム）。接続・順番・再送なし。RFC 768（1980 年）。
QUICUDP の上で TLS 1.3 を組み込んだトランスポート。接続 ID は最大 20 バイト、最初のパケットは 1,200 バイト以上。RFC 9000（2021 年）。HTTP/3 が使う。
