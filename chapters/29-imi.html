型で意味を表す

型検査が捕まえるのは、型として書いた区別だけである。int と string しか書かなければ捕まるのはその取り違えだけで、円とドル、ミリ秒と秒のように同じ数の型で持つ値の取り違えは素通りする。この章では、単位・状態・確かめ済みの値をドメイン（プログラムが扱う対象）の型として書き、意味の取り違えをコンパイルエラーにする方法と、その限りを見る。型だけで持つ区別はコンパイラが一度確かめて消し、値で持つ区別は CPU が実行のたびに確かめるので、型の設計とは、どの区別をどちらに置くかを決めることになる。

構成

    同じ u64 に入るミリ秒・時刻の単位・バイト数を別の型にする（newtype）。取り違えは止まり、費用は 0。

  2. 2値の数

    欄を並べる型は値の数を掛け、場合を並べる型は足す。あり得ない組を表せない型と、そのメモリの並び。

  3. 3作るとき

  4. 4状態と遷移

    状態を値（enum）で持つか、型（typestate）で持つか。コンパイラと CPU の分担。

1同じ数、違う意味 — newtype

u64newtypeE0308rustc 1.95

第28章で見たとおり、型として書いた区別はコンパイラが確かめた後で消え、機械語に費用を残さない。この区別を数の単位に使えば、同じ u64 に入るミリ秒と 12,800 分の 1 秒の取り違えを、コンパイルで止められる。

newtype は Haskell 由来の言葉で、Rust の本は「実行時の性能の損は無く、包んだ型はコンパイル時に消える」と書く。扱う対象を素の数や文字列で持つことを、Fowler と Beck は『Refactoring』で Primitive Obsession と呼んだ。

2値の数を数える — 直積と直和

structenumOptionsize_of

型は、取りうる値の集まりでもある。欄を並べる型と場合を並べる型では、値の数の数え方が違う。数えてみると、意味の無い値が型に入っていないかが分かる。

値の数が掛け算と足し算になるので直積型・直和型と呼び、合わせて代数的データ型という。ML・Haskell の直和型や Rust・Swift の enum は場合ごとに中身を持てるが、C の enum は名前を付けた整数で、中身は持てない。

3作るときに確かめる — 円の型

i64 → Yenスマートコンストラクタchecked_*

外から来た数は、まだ確かめていない。確かめる関数だけが値を作れるようにすると、その型の値はどれも確かめ済みになる。Super Chat の金額のような円の金額を例に、0 以上の整数の型を作る。

Rust は、debug の既定ではあふれを確かめて panic で止め、release の既定では確かめずに折り返す（第28章 場面3）。金額のようにあふれてはいけない値は、checked_ の付いた演算で書いて None を扱う。

4状態と遷移に名前を付ける — 値で持つか、型で持つか

IFrame APImatchtypestate

プレーヤーは再生中・一時停止のような状態を持ち、操作や出来事で次の状態へ移る。状態と遷移を型で書くと、扱い忘れやあり得ない順番をコンパイラが見つける。書き方は、状態を値で持つか型で持つかの 2 通り。

typestate は Strom と Yemini が 1986 年の論文（IEEE TSE）で名付けた考えで、いま許す操作を変数ごとの状態で変え、コンパイラが確かめる。Rust では、値を渡すと元の名前を使えなくなる規則（所有）がこれを支える。

5境界で型を作り直す — バイトに型は付いてこない

JSONprotobufserdezod

型の守りが効くのは、プログラムの中だけである。外から届くバイトには型が付いてこないので、入口で一度だけ確かめてドメインの型に作り直し、中ではその型を信じる。

中で作った値を外へ出すときは、型の区別がバイトから消える。JSON には Ms と Ticks の区別が無く、"pos_ms" のような欄の名前と文書が単位を伝える。受け取る側は、それを入口で型に戻す。

6型にできること・できないこと — 答え

コンパイラ実行時テスト

ここまでの区別を、確かめる時期で 3 つに分ける。コンパイラが実行の前に証明すること、実行のたびに確かめること、テストで確かめること。最後に、型システムの利点は何かという問いに答える。

テストは選んだ入力で道を 1 本ずつ走らせて確かめ、型検査は走らせずに全部の道を確かめる。確かめる中身が違うので、一方で他方の代わりはできない。

7まとめ — 型で意味を表す

  1. 同じ u64 のミリ秒と 12,800 分の 1 秒を newtype で別の型にすると、取り違えが E0308 で止まる。大きさも機械語も元の型と同じで費用は 0。別名（typedef・type）では区別されない（1）。
  2. 直積は値の数を掛け、直和は足す。あり得ない組を表せない型にすると、使う側の確かめが要らなくなる。enum はタグを付けて中身を重ね、中身に取らない値があればタグの代わりに使う（2）。
  3. 確かめる関数だけが値を作れる型（スマートコンストラクタ）は、入口で 1 回確かめた事実を型に残す。どの演算を定義するかが、円の意味を決める（3）。
  4. 実行中の出来事で変わる状態は値（enum）で持ち、コンパイラが漏れを、CPU がタグを確かめる。順番が決まった手順は型（typestate）で持ち、機械語に何も残さない（4）。
  5. 外から来るバイトに型は付いてこない。確かめない as ではなく、入口のパースでドメインの型に作り直し、失敗はそこで扱う（5）。
  6. 型システムの利点は、区別と約束をコンパイラに預けること。意味の取り違えがコンパイルエラーになり、変えたときに直す所が挙がり、実行時の費用は増えず、型で言えない所は境界の検査とテストに回す（6）。
newtype既存の型を中身 1 つの構造体で包み、別の名前の型にしたもの。大きさと機械語は元の型と同じ。Rust の struct Ms(u64)。
ブランド型TypeScript で、型の上だけの欄（__brand など）を足して形を変え、同じ number や string を区別する書き方。実行時の値は変わらない。
構造的型付け型を名前でなく形（欄とその型）で比べること。TypeScript はこれで、Rust と C の構造体は名前で比べる（名前的型付け）。
直積型・直和型欄を並べ、値の数が積になる型（構造体）と、場合を並べ、値の数が和になる型（Rust の enum）。合わせて代数的データ型。
タグ（判別子）直和型の値がどの場合かを示す欄。例の State は先頭の 2 バイト。TypeScript の判別可能な union では kind などのプロパティ。HTML のタグ（第10章）、TLS の改ざん検出のタグ（第20章）とは別。
スマートコンストラクタ中身を隠し、確かめる関数だけが値を作れるようにする書き方。型が保証するのは「その関数を通った」こと。
網羅性の検査match・switch が全部の場合を扱っているかを、コンパイラが確かめること。Rust の E0004。
typestate状態を型の引数で持ち、状態ごとに使える操作をコンパイラが確かめる書き方（Strom・Yemini、1986 年）。状態の型は 0 バイト。
篩型（refinement type）型に条件の式を付けて値を絞った型。{v:Int | v >= 0}。Liquid Haskell は SMT ソルバで確かめる。
Primitive Obsession扱う対象の値を、素の int や文字列のまま持つこと。Fowler『Refactoring』の言葉。
