CPU

第4章の論理ゲートと第5章の記憶を組み合わせると、メモリに置いた「数の列」を命令として読み、順に実行する機械ができる。この章では 8 ビットの小さな架空 CPU（YT-8）を 1 つ決め、1 + 2 + 3 を足すループを実際に走らせながら、レジスタ・ALU・バス・制御装置の役割、命令が数である理由、フェッチ・デコード・実行の手順、クロックとパイプライン、キャッシュ階層を見る。ブラウザの JavaScript も動画のデコードも、最後はこの手順の繰り返しに還元される。

構成

  1. 1CPU の中身

    レジスタ（PC・IR・A・Z）、ALU、制御装置、クロック、メモリと結ぶ 3 種類のバス。箱の中は第4・5章の回路で拡大して見る。

  2. 2命令は数字

    8 ビットの上位 4 ビットが「何を」、下位 4 ビットが「どこ」。6 命令の命令セットと機械語。

  3. 3フェッチ・デコード・実行

    ADD 11 の 1 命令を 5 拍に分けて、バスを流れる番地と中身を追う。解読と加算は、ゲートと加算器の中まで拡大する。

  4. 4小さなプログラムを動かす

    1 + 2 + 3 を足すループ。22 命令で PC・A・Z・メモリがどう変わるか。

  5. 5クロックとパイプライン

    5 段階を重ねて毎拍 1 命令。ハザード、実際の CPU の数字、発熱の壁。

  6. 6キャッシュ階層

    DRAM は 200 拍遠い。L1・L2・L3 の写し、ヒットとミス、局所性、置き換え。

YT-8 はこの章のための架空の CPU。実在の CPU の数値（拍数・容量・周波数）は本文に書いた範囲がおおよその値で、製品によって違う。

1CPU の中身

YT-88 ビットメモリ 16 番地

CPU は、値を一時的に覚えるレジスタ、計算する ALU、全体に合図を出す制御装置をバスで結んだもの。命令もデータも外のメモリに番地付きで置かれ、CPU は番地を指定して読み書きする。

YT-8 はレジスタ 4 つ・命令 6 種類の最小構成。実際の CPU（x86-64 や ARM）はレジスタが数十個、命令が数百種類あるが、部品の種類と役割はこの図と同じ。

2命令は数字

オペコード 4 ビットオペランド 4 ビット

CPU が読むのは8 ビットの数だけ。上位 4 ビットで「何をするか」、下位 4 ビットで「どの番地か」を決めておけば、数の列がそのままプログラムになる。

YT-8 のオペランドは番地 1 つだが、実在の命令はレジスタ番号・定数（即値）・番地を組み合わせたオペランドを持ち、「どのレジスタとどのレジスタを足してどこに置くか」まで 1 命令で指定する。可変長の x86-64 では、命令の切れ目を見つける所からデコードが始まる。

3フェッチ・デコード・実行

ADD 111 命令 = 5 拍

CPU がすることは、命令を取ってくる（フェッチ）、解読する（デコード）、実行する、の繰り返しだけ。番地 1 の命令 ADD 11 を、クロック 1 拍ごとに追う。開始時は PC = 1、A = 0。

実際の CPU は、命令（1・2 拍め）とデータ（4 拍め）の読み出しを別々の L1 キャッシュ（命令用とデータ用）から行うので、2 回のアクセスがぶつからない。5 拍を重ねて毎拍 1 命令にする方法は5「クロックとパイプライン」、キャッシュは6「キャッシュ階層」で見る。

4小さなプログラムを動かす

sum = 1 + 2 + 322 命令

番地 0〜7 のプログラムは「sum に n を足し、n を 1 減らし、n が 0 でなければ番地 0 へ戻る」。JNZ が PC を書き換えることで、同じ 7 命令が 3 周回る。

実機では、CPU がリセット値の番地にある ROM のファームウェアを実行し、それが OS をメモリに読み込む（第9章 場面 1）。条件つきで PC を書き換える JNZ があるから繰り返しと場合分けが書け、JavaScript の for 文も CPU の段階ではこの形になる。

5クロックとパイプライン

IF ID EX MEM WB3 GHz = 0.33 ns

1 命令に 5 拍かける代わりに、5 つの段階を別々の命令で同時に使えば、定常状態では毎拍 1 命令が完了する。クロックは水晶振動子の一定の拍子で、すべての段階がこれに合わせて進む。

1 拍の長さは、いちばん深い段の論理ゲートの段数と配線の遅延で決まる（第3章の充放電）。段を細かく分けるほど周波数は上げられるが、分岐予測が外れたときに捨てる拍も増える。電力は電圧 V の 2 乗で効くので、省電力はまず電圧を下げて稼ぐ。

6キャッシュ階層

L1 / L2 / L3 / DRAMライン 64 B

CPU の 1 拍は約 0.3 ns だが、DRAM から値が返るまで 70〜100 ns、200 拍以上かかる。そこで CPU の中に小さく速い SRAM（第5章）を何段か置き、最近使ったデータの写しを近くに持つ。

容量と拍数はおおよその値（2020 年代のパソコン用 CPU、1 拍 ≈ 0.3 ns）で、製品によって違う。L1 は命令用とデータ用に分かれ、L2 もコアごとに持つ。ヒット率は命令の並びとデータの置き方で変わるので、同じ CPU でもプログラムによって速さが何倍も違う。

7まとめ — 数の列を読んで実行する機械

  1. CPU はレジスタ・ALU・制御装置・クロックをバスで結んだもので、命令もデータも外のメモリに番地付きで置く（1）。
  2. 命令は決まった幅の数。上位ビットが「何を」、下位ビットが「どこ」を表し、数の列がプログラムになる（2）。
  3. 1 命令は、PC の番地から取ってくる → 解読する → 実行する、の順で進み、YT-8 では 5 拍・メモリ 2 回で終わる（3）。
  4. 条件つきで PC を書き換える命令（JNZ）が繰り返しと場合分けを作る。22 命令で 1 + 2 + 3 = 6 が番地 10 に残る（4）。
  5. 5 段階を重ねるパイプラインで毎拍 1 命令。依存と分岐で待ちが出る。周波数は発熱で頭打ちになった（5）。
  6. DRAM は 200 拍以上遠い。L1〜L3 の写しと局所性で平均待ち時間を十数拍に抑える（6）。
レジスタCPU 内部の小さな記憶。フリップフロップの束で、1 拍で読み書きできる。PC（次の命令の番地）、IR（いまの命令）、汎用レジスタ、フラグ。
ALU算術論理演算装置。加算器を中心に、減算（2 の補数の加算）、比較、AND/OR などを行う組み合わせ回路。
制御信号制御装置が命令を解読して各部品に出す合図。どのレジスタを開くか、ALU に何をさせるか、メモリを読むか書くか。
バス複数の部品が共有する配線の束。アドレスバス（番地）、データバス（中身）、制御線。
機械語・アセンブリCPU が読むビット列と、それを人が読める名前で書いたもの。1 対 1 に対応する。
フェッチ・デコード・実行命令サイクル。PC の番地の命令を IR へ、解読、実行。実行後は PC が次の番地を指す。
クロック一定周期の信号。1 拍（サイクル）ごとに各段階が進む。3 GHz なら 1 拍 0.33 ns。
パイプラインIF/ID/EX/MEM/WB の段階を別の命令で同時に使う方式。定常で毎拍 1 命令。依存・分岐でハザード（待ち）が起きる。
キャッシュCPU 内の SRAM にメモリの写しを置く仕組み。L1（4〜5 拍）、L2（約 14 拍）、L3（40〜50 拍）。64 バイトのライン単位で出し入れする。
局所性直前に使った番地（時間的）やその近く（空間的）をまた使う性質。キャッシュが効く理由。
