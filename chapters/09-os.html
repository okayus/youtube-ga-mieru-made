OS

CPU・メモリ・NIC・GPU は、そのままでは1つのプログラムしか相手にできない。OS のカーネルが、それらを数百のプロセスに貸し出し、互いを隔て、装置の違いを隠す。この章では、カーネルとユーザー空間の境界、プロセスとスレッド、システムコールで境界を越える手順、仮想メモリ、スケジューラ、そしてネットワークのパケットがソケットに届くまでを追う。ブラウザ（第10章）はこの章のソケット API を呼び、パケット（第11章以降）はその下で作られる。

1カーネルとユーザー空間

ring 0 / ring 3システムコール・割り込み・例外

プログラムは装置に直接触れない。CPU のモードで区切られたカーネル空間だけが装置と全メモリを扱え、ブラウザなどのユーザー空間は決まった入口からカーネルに頼む。

Linux のカーネルは1つの大きなプログラム（モノリシックカーネル）で、ドライバもネットワークスタックも同じ特権で動く。macOS の XNU や Windows NT も、構成は違うがモードの境界と3つの入口の考え方は同じ。

2プロセスとスレッド

PIDtask_structR / S

YouTube を映している「ブラウザ」は1つのプログラムではなく、役割の違う5つ前後のプロセスの集まり。それぞれが自分のアドレス空間と複数のスレッドを持ち、カーネルの表で管理される。

プロセスの数は、タブと拡張機能ごとに増える。Chrome の「タスクマネージャ」（Shift+Esc）や Linux の ps -eLf で、プロセスとスレッドの実際の一覧が見える。

3システムコール

syscall / sysretrecvfrom = 45

ネットワークから届いたデータをブラウザが受け取る recvfrom() 1回を、レジスタと CPU のモードの切り替えで追う。システムコールは、ユーザー空間がカーネルに仕事を頼む唯一の正規の手段。

往復の費用が無視できないので、ブラウザは 64 KiB のような大きなバッファで一度に受け取り、epoll_wait() で多数のソケットをまとめて待つ。Linux 5.1 以降の io_uring は、複数の要求を1回の境界越えで出せる。

4仮想メモリ

4 KiB ページ4段のページテーブルTLB

プロセスが使う番地（仮想アドレス）と DRAM の番地（物理アドレス）は別物で、カーネルが作る対応表で結ばれる。この仕組みが、プロセスどうしの隔離、共有メモリ、ページキャッシュを同時に実現する。

4 KiB のページだと大きなメモリで表が巨大になるので、2 MiB や 1 GiB のヒュージページも使える。レンダラのアドレス空間は /proc/<pid>/maps で、TLB のミス回数は perf stat -e dTLB-load-misses で実測できる。

5スケジューラ

HZ=1000CFS / EEVDFコンテキストスイッチ

コアの数より多いタスクを、タイマー割り込みの刻みで交代させる。スケジューラは次に走るタスクを選び、コンテキストスイッチでレジスタを入れ替える。再生中のブラウザは、ほとんどの時間を待ちで過ごす。

図の時間軸は実時間の 500 分の 1。実際の 1 ms の刻みは、図では 0.5 秒。top の %us・%sy・%id、/proc/sched_debug、perf sched で、取り分と切り替えの実測が見える。

6ドライバとネットワークスタック

DMANAPIsk_buffソケット

動画のデータは、NIC が DMA でメモリに置いたフレームとして始まり、ドライバ・IP・UDP の各層でヘッダを外されてソケットに届き、待っていたブラウザのプロセスを起こす。この道の上端がソケット API。

1080p（約 5 Mbps）では 1 秒に約 400〜600 パケット、4K では数千パケットがこの道を通る。ethtool -S でリングの統計、ss -tunp でソケットとプロセスの対応、/proc/interrupts で割り込みの回数が見える。

7まとめ — OS は何を貸し、何を隔てるか

  1. CPU の2つのモードがカーネル空間とユーザー空間を分け、境界を越える入口はシステムコール・割り込み・例外の3つだけ（1）。
  2. ブラウザは役割ごとの複数のプロセスでできている。プロセスはアドレス空間と資源の単位、スレッドは実行の流れの単位（2）。
  3. システムコールは番号と引数をレジスタに置いて syscall。入口でモードを切り替え、表を引いて処理し、sysret で戻る（3）。
  4. 仮想アドレスは4段の表で物理アドレスに変換され、TLB が控える。対応が無ければページフォールトでカーネルが割り当てる（4）。
  5. タイマー割り込みの刻みで vruntime の小さいタスクを選び、レジスタを入れ替える。待つタスクは CPU を使わず、届いたら起きる（5）。
  6. パケットは NIC の DMA から層を上がってソケットに届き、プロセスを起こす。ユーザー空間から見える境界はソケット API だけ（6）。
カーネル／ユーザー空間特権モード（ring 0 / EL1）で動く OS の中核と、制限モード（ring 3 / EL0）で動くプログラムの領域。
システムコール番号で頼むカーネルの入口。x86-64 Linux では read=0、write=1、socket=41、sendto=44、recvfrom=45、epoll_wait=232。往復 0.1〜0.5 µs 程度。
割り込み・例外装置からの通知と、CPU が検出した異常（ページフォールトなど）。どちらも決まったハンドラへ飛ぶ。
プロセス／スレッドアドレス空間・fd 表・権限の単位と、その中の実行の流れ。Linux ではどちらも task_struct。
ページ・ページテーブル・TLB4 KiB の単位、仮想→物理の4段の対応表（根は CR3）、その控え（数十〜数千エントリ）。
ページフォールト対応の無いページへのアクセスで起きる例外。デマンドページングの要。不正なら SIGSEGV。
スケジューラ・vruntime次に走るタスクを選ぶ仕組み。CFS は重み付き実行時間が最小のものを選ぶ。Linux 6.6 から EEVDF。
コンテキストスイッチレジスタと CR3 の入れ替え。直接の費用は数 µs。
受信リング・DMA・NAPINIC が直接書き込む記述子の環、CPU を介さない転送、割り込みを抑えてまとめて処理する方式。
ソケットプロセスとネットワークスタックの接点。socket / connect / sendto / recvfrom / epoll で操作する。
