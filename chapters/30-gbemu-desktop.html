エミュレータの外側

Rust で書かれたゲームボーイのエミュレータ gb-emu のうち、PC で動かす側の 218 行（gb-emu-desktop）を読む。CPU や画面の回路を真似る本体は別のクレート gbemu に任せ、この側は本体の時計を実時間に合わせ、キーボードをボタンに、画素の列を窓に、音のサンプルをスピーカーに、セーブをファイルにつなぐ。つまり第4〜8章の機械をソフトウェアで作り直したものと、第9章の OS との境目である。コードは具体的な値を入れて 1 行ずつ追う。

1全体の形 — main から Emulator へ

main.rs218 行SDL2struct

第29章までに見た層を、1 つのプログラムの上で見直す。gb-emu-desktop は 3 ファイル・218 行で、ROM を読み、本体（GameBoy）を作り、SDL で窓・音・キーボードを開き、本体の時計を回す。

本体の gbemu クレートは約 4,000 行で、CPU（SM83）・PPU・APU・カートリッジ・タイマ・ジョイパッド・シリアルを持つ。この章は外側だけを読み、本体の中は入口の emulate_cycle と、外側が触る欄にとどめる。

2時計を合わせる — 1 M サイクル ＝ 953 ns

4,194,304 Hzu128Instant'running

本体は「1 M サイクル進め」と言われた分だけ進む。実時間とそろえるのは外側の仕事で、run は起動からの経過ナノ秒を 953 で割った回数だけ emulate_cycle を呼ぶ。待つ命令は無い。

953 は 4 × 10⁹ ÷ 4,194,304 の整数除算で、正確な 953.674… より 0.07% 短い。この時計だけなら 1 時間に約 2.5 秒速く進む計算だが、場面5 の音の待ちのほうが強く効くので、実際の速さは音の側で決まる（計算上）。

3キーボードをボタンに — key2joy と P1

$FF00Option<Button>&mutIF ビット 4

W・A・S・D と 1〜4 のキーが、ゲームボーイの 8 つのボタンになる。SDL のイベントを match で Button に写し、本体のジョイパッドのビットを 0 に倒し、割り込みの旗を立てる。

Pan Docs によれば、P1 の下位 4 ビットは 0 が「押されている」で、ビット 5・4 に 0 を書いてどちらの組を読むかを選ぶ。ジョイパッド割り込み（IF のビット 4、飛び先 $60）は、選んだ組の下位のビットが 1 から 0 に変わったときに要求される。

4画素の列を窓に — LCD::draw

160×144RGBA32pitch 640×4

本体の PPU は 1 フレームぶんの画素を 92,160 バイトの列に書く。外側はフレームの終わりに 1 回だけ、その列を SDL のテクスチャに写し、窓の大きさに引き伸ばして出す。

これは第8章 場面1 のフレームバッファをソフトウェアで持ったもの。SDL の先は OS のウィンドウシステムと GPU（第8章 場面2）で、present は垂直同期を待つ設定にしていないので、ティアリング（第8章 場面3）が出ることはある。

5サンプルをスピーカーに — Audio と背圧

48,000 Hzf32 × 28,192 バイトdyn Fn

本体の APU は 512 組のステレオのサンプルがたまるたびに関数を 1 回呼ぶ。外側はその関数として、SDL の音のキューに積むクロージャを渡す。キューがたまりすぎると、外側は寝て待つ。

PCM のサンプルは第8章 場面6 の数値の列そのもので、この後は OS のオーディオの層、DAC、アンプ、スピーカーへ進む。キューは第27章 場面5 のリングバッファと同じ役で、作る側と使う側の速さの差を吸収する。

6セーブとケーブル — ファイルと 0xFF

.SAVResult$0134SB／SC

カートリッジの電池で残る RAM（SRAM）は、PC ではファイルになる。Enter で中身を書き出し、起動の引数で読み戻す。通信ケーブルの相手はいないので、送るたびに 0xFF が返る。

ファイルを作る・書く・閉じるは第9章 場面3 のシステムコール（open・write・close）になる。SB・SC（$FF01・$FF02）や P1 は第7章 場面2 のデバイスレジスタで、本体はメモリの番地として見せ、match で部品に振り分けている。

7まとめ — エミュレータの外側

  1. 外側は 218 行。ROM を Vec<u8> に読み、本体 GameBoy を作り、SDL で窓・音・キーボードを開く。本体は第4〜8章の機械、SDL の外は第9章の OS。持ち主は struct Emulator（1）。
  2. 時計は外側が合わせる。経過ナノ秒 ÷ 953 の回数だけ emulate_cycle を呼び、待たずに回り続ける。1 フレーム ＝ 17,556 M サイクル（2）。
  3. キーは match で Option<Button> に写し、P1 のビットを 0 に倒し、IF のビット 4 を立てる。同じ構造体の別の欄なら &mut を 2 つ同時に取れる（3）。
  4. 画面は 92,160 バイトの列。フレームの終わりに 1 回、ピッチ 640 でテクスチャに写し、640×576 の窓へ引き伸ばす（4）。
  5. 音は 512 組ごとにクロージャへ。キューが 8,192 バイトを超えると 1 ms 寝る。計算上、この待ちが全体の速さを決める（5）。
  6. セーブは SRAM を「題名.SAV」に書き、失敗は eprintln! で知らせて続ける。ケーブルの相手がいないので、送るたびに 0xFF を受け取ったことにする（6）。
M サイクル本体の時間の単位。クロック（4,194,304 Hz）の 4 拍で、約 953.67 ns。外側は整数除算で 953 ns として数える。
フレーム（PPU）PPU が 154 行を描き終える周期。本体では 1 行 114 M サイクル、1 フレーム 17,556 M サイクル（約 16.74 ms、59.73 Hz）。映像の 1 枚の画（第8章）と同じ意味。
P1／JOYP（$FF00）ジョイパッドのレジスタ。ビット 5・4 に 0 を書いてボタンの組か十字の組を選び、下位 4 ビットは 0 が「押されている」（負論理）。
IF（$FF0F）・IE（$FFFF）割り込みの要求と許可の旗。ビット 0 VBlank、1 STAT、2 タイマ、3 シリアル、4 ジョイパッド。飛び先は $40・$48・$50・$58・$60。
buffer（フレームバッファ）本体の PPU が書く Vec<u8>。160 × 144 画素 × RGBA 4 バイト ＝ 92,160 バイト。1 行は 640 バイト（ピッチ）。
サンプルとキュー48,000 Hz・ステレオ・f32 の PCM。512 組（4,096 バイト）ごとに SDL のキューに積み、未再生が 8,192 バイト（21.3 ms）を超えたら 1 ms 待つ。
SRAM（セーブ）カートリッジの電池付き RAM。大きさはヘッダ $0149 の符号で 0〜128 KiB。PC では「題名.SAV」のファイルにする。
SB・SC（$FF01・$FF02）シリアル通信のデータと制御のレジスタ。SC のビット 7 で開始、ビット 0 で内部クロック。相手がいなければ 0xFF を受け取る（Pan Docs）。
クロージャと dyn Fn外の変数を捕まえた関数。move で持ち主ごと中に移す。Box<dyn Fn(&[f32])> は「&[f32] を受け取る何らかの関数」の箱、Rc は持ち主を数えて共有する包み。
分割借用同じ構造体でも別の欄なら &mut を同時に取れる規則。joypad と cpu.interrupts を同時に渡せる理由。全体を &mut で渡すと E0499。
